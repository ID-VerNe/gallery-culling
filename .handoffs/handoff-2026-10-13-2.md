### 2.2 具体改动清单

#### A. 三条数据丢失/正确性缺陷（P0）

**BE-01 — xmp reject 清空镜头与调色**
`src-tauri/src/xmp.rs`：`write_xmp` 的 reject 分支读了 `meta` 却转手调 `write_xmp_rating_minus_one`，后者构造 `XmpMetadata{..Default::default()}` 空壳。改为直接复用已读出的 `meta`：
```rust
meta.rating = 0;
meta.label = String::new();
meta.rejected = true;
return write_xmp_preserving(image_path, &meta);
```
回归测试 `rejecting_a_toned_photo_preserves_lens_and_tone` 断言 9 个字段全部存活。

**BE-02 — 畸形 XMP 静默覆盖**
`append_our_block` 找不到 `</rdf:RDF>` 时回退 `build_fresh_document(&XmpMetadata::default())`，**连调用方已读的 meta 也丢弃**（比原计划描述更严重）。签名由 `-> String` 改为 `-> Result<String, String>`，`write_xmp_preserving` 用 `?` 传播。

**BL-02 — 进程死亡被当成超时**
`src-tauri/src/lumen.rs` 新增 `LumenError::ProcessExited`：
- `Timeout` → `Ok(None)`（进程活着，可重试）
- `Disconnected` → `Err(ProcessExited)`（stdout 关闭，须重启 sidecar）

**P0-VER — 三处在途 WIP 的真实缺陷**（原计划完全未覆盖）
1. `ThumbnailGrid.tsx:450` 高亮真值由**互斥**改为**并集**：
```tsx
const isSelected = itemIndex === selectedIndex || activeIds.has(group.id);
```
原写法「集合非空就完全以集合为准」，而键盘导航只更新 `selectedIndex` 不碰 `selectedIds`，导致宫格高亮与实际被评级的照片脱钩。
2. `App.tsx` `handleRate`：`rating>0 && flag==='reject'` 时发 `flag='none'`（打星解除淘汰；pick 保持不变）。
3. 空格「设为基准」原本复用 `onPinRight`（钉右窗格），单图视口下会钉错照片。新增 `useKeyboardShortcuts` 的 `onTogglePinCurrent` + `App.tsx` 的 `handleTogglePinCurrent`。

#### B. UX 修复（22 项，全部完成）

要点：
- **UX-06**：15 个文件 81 处 `border-white/10` → `border-default`、`bg-white/5` → `bg-background-surface-hover`。副作用：边框明显变亮，这是修 WCAG 1.4.11 的预期结果，不是回归。

## 4. 项目约定参考

### 4.1 规则来源

**仓库内没有 CLAUDE.md。** 规则在全局 `~/.claude/CLAUDE.md`（含 `@CLAUDE_MEMORY.md`）。与本项目相关的 7 条：

1. **不保留向后兼容** —— 删过时路径，不加兼容层/回退/迁移（FE-05、FE-12、BL-05、BE-12/13 均据此）
2. **最简实现** —— 不投机抽象/配置/间接层（FE-01 Button 被跳过的直接理由）
3. **分层增长** —— 从最小可用版本起步
4. **模块化 + 职责分离**
5. **优先成熟库** —— 不 reimplement 常见功能
6. **长期架构决策** —— 不接 stopgap
7. **禁止 emoji** —— 回复、代码、注释、commit message 中都不允许（UX-33）

### 4.2 设计令牌（重要）

全部定义在 `src/styles/design-tokens.css`（仅 29 行）+ `src/index.css`，经 `tailwind.config.js` 暴露为工具类：

| 令牌 | 工具类 | 值 |
|------|--------|-----|
| `--color-bg-surface-hover` | `bg-background-surface-hover` | `rgb(255 255 255 / 5%)` |
| `--color-border-subtle` | `border-subtle` | 6% |
| `--color-border-default` | `border-default` | 20% |
| `--color-border-strong` | `border-strong` | 35% |

**禁止**再写 `border-white/10` / `bg-white/5` 这类硬编码透明度 —— 原因有二：低于 WCAG 1.4.11 的 3:1；且 `index.css` 的 `@media (prefers-contrast: more)` 只重定义令牌变量，硬编码类根本不消费（高对比偏好失效）。

自定义工具类：`.focus-ring`（焦点环，含 forced-colors 回退）、`.tone-slider`（命中区 24px / 绘制轨道 4px）、`.tap-target`（min-w/h 24px）。

### 4.3 架构约定（不要推翻）

以下来自 DRY/SRP 审计 §9 的**反向结论**，是刻意的不合并：

- **`luminar.rs` 与 `lumen.rs` 不合并** —— 不同产品（Skylum vs lumen-cli）、不同协议（Photoshop plugin vs JSON-RPC MCP）、不同传输（同步 vs 常驻 sidecar）
- **`taskApi.ts` / `lumenApi.ts` 不并入 `api.ts`** —— 有文档化的架构理由；真正该拆的是 `api.ts` 这个上帝对象
- **`useKeyboardShortcuts.ts` 不物理拆分** —— guard 链顺序敏感，只重构 switch 为函数表
- **`Modal.tsx` 不动结构** —— 5 个弹窗全部正确复用它，是范本；UX-17 只做增量增强
- **三视口已有共享层**（`zoomAtPoint`/`useLumenPreview`/`getToneFilterString`/`ViewportEmptyStateView`）抽得干净，不要动
- **`luminar.rs` 的 `prepare_tiff`、`query_registry_path` 提取仍待做**

### 4.4 关键契约（改动时必须守住）

| 契约 | 位置 |
